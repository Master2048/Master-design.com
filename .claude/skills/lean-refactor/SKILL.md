# lean-refactor: оптимизация блока без поломок

Цель: тот же пиксель, та же логика, меньше и чище кода.
Главный критерий успеха: **нулевой diff вычисленных стилей и геометрии** до и после правок. Красота кода на втором месте.

Аргумент: `$ARGUMENTS`, имя BEM-блока (`faq`, `stats`, `navbar`, `case-card`...). Флаг `--plan-only`: только анализ и план, без правок.

Дополнительные файлы скилла (читай по ходу работы, а не все сразу):
- `references/css.md` - что в CSS можно менять, что нельзя, и ловушки каскада.
- `references/js.md` - то же для JS: тайминги, ScrollTrigger, обработчики.
- `scripts/snapshot.js` - снимок вычисленных стилей и сравнение (запускается в браузере).

---

## Шаг 0. Точка отката

1. `git status --short` и `git diff --stat`. Если в `style.css`, `script.js` или `index.html` есть незакоммиченные правки, **не коммить сам**. Скопируй эти файлы в scratchpad (`backup-<время>/`) и скажи пользователю, где лежит бэкап.
2. Запиши метрики «до» для отчёта: строки и байты CSS-правил блока и JS-функции блока (их границы находятся на шаге 1).

## Шаг 1. Карта блока: что в зоне правок, что только читать

Собери полную карту **до** любых правок. Пропущенная зависимость - главная причина поломок.

**HTML** (`index.html`, плюс `offer.html`, `privacy.html`, если блок там есть):
- Найди `<section class="<блок> ...">` или корневой элемент компонента. Запиши селектор корня для снимка (обычно `#id` или `.<блок>`).
- Выпиши все классы, `js-*` хуки, `data-*` атрибуты и `id` внутри блока.

**CSS** (`style.css`): ищи все места, где упоминается блок, а не только основной кусок.
```bash
grep -n "\.<блок>\b\|\.<блок>__\|\.<блок>--" style.css
```
Блок обычно разбросан по файлу. Проверь отдельно:
- медиазапросы в других частях файла (мобильные правки часто лежат в конце `style.css`);
- `.q-low` / `.q-mid` / `.q-high`, `.lite-android`, `.js` / `.no-js`;
- `@media (prefers-reduced-motion: reduce)`, `@supports`, `@keyframes`, которые использует блок;
- критический CSS в `<head>` файла `index.html` (`chunk:head-critical-css`);
- токены `design-tokens.css`, которые использует блок (они только для чтения).

**JS** (`script.js`):
- функция `init<Блок>()` и хелперы, которые вызываются **только** из неё;
- все строки, где упоминаются классы и хуки блока: `grep -n "<блок>" script.js`;
- классы состояний, которые ставит JS (`is-*`, `has-*`), и CSS-переменные, которые JS пишет (`--x`, `--rail-side`...). Для CSS это внешний контракт: имена не меняем.

**Общие компоненты внутри блока** (`.btn`, `.glass`, `.section-title`, `.container`, `.text-gradient`, `.icon`, `.status-badge`, общие хелперы `$`, `$$`, `clamp`, `MOTION`, `prepareGlitch`, `decodeText`...) **в зону правок не входят**. Их правка задевает другие секции. Если там видна проблема, внеси её в отчёт как отдельное предложение.

Итог шага: таблица «файл : диапазоны строк : в зоне / только читать».

## Шаг 2. Эталон (baseline)

Без эталона правки не начинаем. Проверка «на глаз» здесь не годится.

1. `preview_start {name: "static"}` (конфиг в `.claude/launch.json`). Если порт 5299 уже занят сервером другого чата, открой `http://localhost:5299/` через `navigate`. Если сервер недоступен совсем, сообщи пользователю и остановись: без проверки в браузере скилл не работает.
   Скрипт снимков удобно подгружать прямо со статик-сервера: `eval(await fetch('/.claude/skills/lean-refactor/scripts/snapshot.js').then(r => r.text()))`.
2. Для каждой ширины **375×812, 768×1024, 1024×768, 1440×900**:
   1. `resize_window` на эту ширину, затем **перезагрузи страницу**: `script.js` читает `matchMedia` и уровень качества один раз при старте.
   2. Дождись конца прелоадера (≈3-5 с), прокрути блок в видимую область (`scrollIntoView` через javascript_tool или `computer scroll`), подожди ещё 3 с, чтобы reveal-анимации доиграли.
   3. Прочитай `scripts/snapshot.js` и выполни через `javascript_tool` его содержимое плюс вызов `__lean.snap('<селектор корня>', 'base-<ширина>')`.
   4. **Повторный снимок для отсева шума:** перезагрузи, повтори пункт 2, сними `base2-<ширина>`. Затем `__lean.diff('base-<w>', 'base2-<w>')`: всё, что отличается, - недетерминированные свойства (анимации, частицы, случайность). Diff после правок их проигнорирует.
   5. Скриншот блока (`computer screenshot`) для отчёта.
3. **Состояния.** Если у блока есть интерактивные состояния (открытый пункт FAQ, открытое меню, hover-карточка с линзой, ошибка формы), воспроизведи каждое кликом или `form_input` и сними отдельный снимок `base-<w>-<состояние>`. Это нужно минимум на 375 и 1440.
4. Запиши `read_console_messages` (ошибки, которые были ещё до правок, не твои).

Если `meta.rootCls` у двух базовых снимков разный (FPS-замер понизил качество), перезагрузи и сними заново, пока классы не совпадут.

## Шаг 3. План правок

Пройди код блока по чек-листам из `references/css.md` и `references/js.md`. Каждую найденную правку отнеси к одной из категорий:

| Категория | Что это | Действие |
|---|---|---|
| **SAFE** | Эквивалентное преобразование, результат вычисляется однозначно (шорткат без сброса чужих свойств, дубль в том же контексте каскада, мёртвый код, подтверждённый grep-ом) | применяем |
| **CHECK** | Эквивалентно, но зависит от каскада или порядка (перенос медиазапроса, слияние правил через промежуточные правила, делегирование событий) | применяем по одной, после каждой снимаем diff |
| **VISUAL** | Меняет картинку или поведение, пусть и в лучшую сторону (`clamp()` вместо ступенек, новый easing, другое число) | **не применяем**, только в отчёт как предложение |
| **SHARED** | Касается общего компонента или хелпера | не применяем, в отчёт |

С флагом `--plan-only` выведи план таблицей (строка, было → станет, категория, выигрыш) и остановись.

## Шаг 4. Правки

- Порядок: сначала CSS, потом JS. Не смешивай их в одном шаге.
- Правь маленькими партиями: 3-6 SAFE-правок или **одна** CHECK-правка за раз.
- После каждой партии: перезагрузка, снимок `after-<w>`, `__lean.diff('base-<w>', 'after-<w>', 'base2-<w>')` хотя бы на одной ширине (той, которую правка касается). Полный прогон по всем ширинам - в шаге 5.
- Diff не пустой: **откати последнюю партию** и разберись, почему. Не «чини» diff новыми правками поверх.
- HTML не меняй: ни классы, ни структуру, ни атрибуты. От структуры DOM зависят JS, будущие чанки MODX и сам снимок.
- Стиль кода держи как в файле: плоский BEM без CSS-nesting, разделители `/* ---------- Имя ---------- */`, комментарии на русском, короткое тире `-`.
- Комментарии «почему» сохраняй, это документация проекта. Удаляй только комментарии к удалённому коду и устаревшие (те, что описывают уже не существующее поведение).

## Шаг 5. Финальная проверка

На **всех 4 ширинах и во всех снятых состояниях**:
1. Перезагрузка, снимок `after-<w>[-состояние]`, `__lean.diff(base, after, base2)`. Норма: `count: 0`. Любое расхождение - откат конкретной правки.
2. Повтори интерактив вручную: клик, hover, клавиатура (Tab, Enter, Space, Esc), открытие и закрытие.
3. `read_console_messages {onlyErrors: true}`: новых ошибок нет.
4. Скриншоты для сравнения с эталонными.
5. Что снимок не ловит, проверь по коду и опиши в отчёте: `:hover`/`:focus-visible` (наведи `computer hover` и сравни скриншоты), `prefers-reduced-motion`, `q-low`, анимации в процессе (easing и длительности не трогались?), touch-ветки.

## Шаг 6. Завершение

1. Подними `?v=` у `style.css` и/или `script.js` во **всех** HTML-файлах, где они подключены (`index.html`, `offer.html`, `privacy.html`): в `.htaccess` кэш на 30 дней.
2. Очисти снимки: `__lean.clear()`.
3. Сбрось эмуляцию размера: `resize_window {preset: "desktop"}`.
4. Не коммить без просьбы пользователя.

## Отчёт пользователю

Коротко, по-русски:
- **Блок и зона:** какие диапазоны строк правились.
- **Итог:** CSS было → стало (строк и байт), JS было → стало.
- **Проверка:** ширины × состояния, diff = 0, ошибок в консоли нет (или честно, что не прошло и почему).
- **Что сделано:** 3-8 пунктов по сути, без перечисления каждой строки.
- **Не применено** (VISUAL / SHARED): список предложений с пояснением, что изменится визуально.
- **Откат:** где бэкап или какая команда git.
