# JS: правила безопасной оптимизации

Главный закон: **те же эффекты в том же порядке и в те же моменты времени**. В `script.js` поведение держится на трёх вещах, которые легко сломать незаметно:
1. **Порядок создания ScrollTrigger-ов.** От него зависят pin-spacing, расчёт позиций и `refresh()`. Hero и showreel пинятся, все триггеры ниже них считаются с поправкой.
2. **Тайминг.** rAF, `setTimeout`, промисы, `onComplete`, события `seeked` и `animationend`.
3. **Контракт с CSS и HTML.** Классы состояний, `js-*` хуки, `data-*`, CSS-переменные, которые пишет JS.

Контекст файла: всё лежит внутри одного IIFE с `'use strict'`. Хелперы: `$`, `$$` (возвращает **массив**), `clamp`, `mq`, `media`, `MOTION`, `quality`, `hasGsap`, `liteAndroid`. Порядок старта описан в `design-system.md`, раздел 16.

## 1. SAFE

### 1.1 Использовать существующие хелперы
`document.querySelector(x)` → `$(x)`, `Array.from(document.querySelectorAll(x))` / `[...document.querySelectorAll(x)]` → `$$(x)`, `Math.min(max, Math.max(min, v))` → `clamp(v, min, max)`. GSAP-строки easing → `MOTION.ease.*`, только если строка **точно совпадает** (`'expo.out'` → `MOTION.ease.premium`).

`$$` возвращает массив, а `querySelectorAll` - NodeList. Если дальше вызывается `.filter`/`.map`, это только плюс. Но если код где-то полагается на «живость» коллекции (`getElementsByClassName`), это не SAFE.

### 1.2 Повторные запросы DOM
Один и тот же `$('.x')` внутри функции 2+ раза → одна `const`. Условия:
- элемент **статичный**: есть в HTML на момент вызова и не пересоздаётся (SplitText, клоны glitch и marquee, `innerHTML =` пересоздают элементы);
- запрос не стоит внутри обработчика, который должен видеть **текущее** состояние DOM.

Кэшировать в замыкание init-функции можно. Выносить на уровень модуля нельзя: до `DOMContentLoaded` элемента может не быть, а скрипт с `defer` и порядок старта это не гарантирует для поздних модулей.

### 1.3 Синтаксическое сжатие без смены семантики
| Было | Стало | Условие |
|---|---|---|
| `if (a) { return b; } else { return c; }` | `return a ? b : c;` | ветки только `return` |
| вложенные `if` | ранний `return` | без кода после блока, который должен выполниться |
| `const x = obj.x; const y = obj.y;` | `const { x, y } = obj;` | |
| `a && a.b && a.b()` | `a?.b?.()` | **только** если `a` бывает `null`/`undefined`. `?.` не ловит `0`, `''`, `false`, а `&&` ловит |
| `x !== null && x !== undefined ? x : d` | `x ?? d` | |
| `x \|\| d` | **не менять** на `??` | `\|\|` заменяет и `0`/`''`, это другая семантика |
| `function () {}` в коллбэке | `() => {}` | только если внутри нет `this`, `arguments`, `new.target` и функция не используется как конструктор |
| `arr.forEach` ↔ `for…of` | любое | без `break`/`return`-логики, которая меняет смысл |
| `el.style.setProperty('--x', v)` в цикле с одним `el` | без изменений | запись CSS-переменных не трогать |

### 1.4 Мёртвый код
Удалять можно функции, константы и ветки, которые не вызываются нигде (grep по `script.js` и HTML на `on*=`). Чего не трогать:
- флаги и TODO: `DEV_SKIP_PRELOADER`, `METRIKA_ID`, `TODO(MODX)`, это будущая функциональность;
- функции, описанные в `design-system.md` как публичный API (`prepareGlitch`, `glitch`, `GLITCH_PRESETS`, `TRAIL_TOKENS`...);
- ветки под `quality === 'low'`, `media.reducedMotion`, `liteAndroid`, `!hasGsap`, `file://` - на твоём устройстве они «мёртвые», но живые у пользователей.

### 1.5 Дублирование
Одинаковый фрагмент 3+ раза в зоне правок → локальная функция внутри init-функции блока. Не выноси её в общие хелперы: это уже SHARED.

### 1.6 `{ passive: true }`
У `scroll`, `touchstart`, `touchmove`, `wheel` можно добавить, если в обработчике **нет** `preventDefault()`. Добавлять `passive` туда, где `preventDefault` есть, нельзя: сломается отмена (свайп-меню, кастомный скролл).

## 2. CHECK: по одной, с проверкой интерактива

### 2.1 Делегирование событий
N обработчиков на элементах → один на контейнере. Что меняется:
- `e.currentTarget` (был элемент, стал контейнер). Нужен `e.target.closest('.x')` и проверка, что он внутри контейнера;
- порядок срабатывания относительно других обработчиков и `stopPropagation`;
- обработка элементов, добавленных позже (это плюс, но и новое поведение);
- `mouseenter`/`mouseleave`/`focus`/`blur` **не всплывают**. Их нельзя делегировать «в лоб», нужны `mouseover`/`focusin` с проверкой `relatedTarget`.

Для блока с 4-6 элементами выигрыш близок к нулю. Делай, только если реально сокращает код.

### 2.2 Слияние GSAP-анимаций
Два `gsap.to` одного элемента → один, или отдельные твины → `gsap.timeline()`. Таймлайн меняет:
- момент старта (позиция в таймлайне против немедленного старта);
- `overwrite` и конфликт твинов на одном свойстве;
- поведение `onComplete`.

Только если значения, длительности, easing и задержки переносятся **один в один**, с явными позициями (`'<'`, `'+=0.2'`, число).

### 2.3 Чтение и запись layout
Разделить чтения (`getBoundingClientRect`, `offsetWidth`) и записи (`style`, `classList`) против layout thrashing - хорошая оптимизация. Но если чтение стоит **после** записи намеренно (замер нового размера), перестановка даст старое значение. Проверяй каждый случай.

## 3. Запрещено без явного согласия пользователя (VISUAL / поведение)

- Менять порядок вызовов `init*()` в стартовой последовательности и порядок создания `ScrollTrigger.create` / `scrollTrigger: {}` внутри модуля.
- Трогать `ScrollTrigger.refresh()`, `invalidateOnRefresh`, `pin`, `pinSpacing`, `start`/`end`, `scrub`, `anticipatePin`, `pinSettings()`.
- Менять числа: длительности, задержки, пороги, интервалы троттлинга (150 мс у токенов кода, 600 мс у гашения и т.п.), размеры, вероятности.
- Заменять GSAP на CSS-анимации или WAAPI и наоборот.
- Менять `rAF` ↔ `setTimeout`, `await` ↔ `.then`, порядок `await`-ов, `defer` и `async`.
- Убирать `clearProps`, `kill()`, `revert()`, `removeEventListener`, `disconnect()` у observer-ов («кажется лишним»).
- Менять условия `gsap.matchMedia`, `media.*`, `quality`, брейкпоинты.
- Переименовывать функции, константы, классы, `data-*`, CSS-переменные, которые видны снаружи init-функции.
- Добавлять зависимости и библиотеки, переводить код на модули.

## 4. Ловушки, характерные для этого проекта

- **SplitText** пересоздаёт DOM заголовков. Ссылки на дочерние узлы, взятые до `split()`, после него указывают на отсоединённые узлы. Градиентное слово исключено через `ignore`, не трогать.
- **ScrollSmoother**: `window.scrollY` и `scrollTo` работают не так, как без него. Для прокрутки есть `scrollToTarget()`, её и используй.
- **`details`/`summary` (FAQ)**: `el.open` и `toggle` - нативная семантика. Обработчик клика делает `preventDefault()`, только если есть GSAP и нет reduced motion. Без GSAP работает нативное поведение, эту развилку не схлопывать.
- **ScrollVideo**: seek только после `seeked`. Очередь seek-ов и `currentTime` не трогать.
- **Glitch**: копии снимаются в момент запуска. Не кэшировать содержимое заранее.
- **Слабые устройства**: `liteAndroid` и `q-low` - отдельные ветки, их надо читать, даже если они короткие.

## 5. Чек-лист прохода по JS блока

1. Найти `init<Блок>()` и хелперы, которые используются только им.
2. Прямые `document.querySelector*` → `$`/`$$` (1.1).
3. Повторные запросы статичных элементов → `const` (1.2).
4. Синтаксис: ранние `return`, деструктуризация, `?.`/`??` по таблице 1.3.
5. Дубли 3+ раза → локальная функция (1.5).
6. Мёртвый код с проверкой исключений (1.4).
7. `passive` у scroll/touch без `preventDefault` (1.6).
8. Делегирование и слияние твинов - только если реально сокращает код (2.x, CHECK).
9. Всё из раздела 3 → в отчёт как предложение.
10. После правок: каждый интерактив блока руками (клик, клавиатура, повторное открытие, быстрое двойное нажатие) и консоль без ошибок.
