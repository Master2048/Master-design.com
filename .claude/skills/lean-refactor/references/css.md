# CSS: правила безопасной оптимизации

Главный закон: **вычисленное значение каждого свойства каждого элемента должно остаться тем же**. Оно зависит от трёх вещей: специфичности, порядка в файле и контекста (`@media`, `@supports`, класс на `<html>`). Правка, которая меняет хоть одну из них, - уже не SAFE.

---

## 1. SAFE: можно применять партиями

### 1.1 Дубли в одном контексте
Два правила с **одинаковым селектором** в **одном** контексте (одинаковый `@media`, или оба вне медиа), и между ними нет правил, которые задевают те же элементы и те же свойства, - сливаем в одно. Позже объявленное значение побеждает, поэтому при слиянии сохраняем значение из нижнего правила.

```css
/* было */
.faq__item { border-bottom: 1px solid var(--color-border); }
/* ...30 строк других блоков... */
.faq__item { padding-block: var(--space-4); }

/* стало (если между ними никто не трогает .faq__item) */
.faq__item {
  border-bottom: 1px solid var(--color-border);
  padding-block: var(--space-4);
}
```

### 1.2 Повторяющиеся объявления внутри правила
`color: x; ... color: y;` в одном правиле: оставляем последнее. Исключение: **fallback-пары** вида `height: 100vh; height: 100dvh;` или `background: #000; background: color-mix(...)`. Это намеренная деградация для старых браузеров, их не трогаем.

### 1.3 Логические шорткаты (без побочных сбросов)
| Было | Стало | Условие |
|---|---|---|
| `top:0; right:0; bottom:0; left:0` | `inset: 0` | все четыре заданы в этом же правиле |
| `margin-left:auto; margin-right:auto` | `margin-inline: auto` | |
| `padding-top:X; padding-bottom:X` | `padding-block: X` | |
| `align-items:c; justify-items:c` | `place-items: c` | |
| `align-content:c; justify-content:c` | `place-content: c` | |
| `row-gap:X; column-gap:X` | `gap: X` | |
| `width:X; height:X` | `inline-size`/`block-size` не меняем: в проекте используются физические | **не трогать** |
| `overflow-x:h; overflow-y:h` | `overflow: hidden` | |

Шорткат **полностью** заменяет набор длинных свойств, но **не сбрасывает чужие**. Опасные шорткаты в разделе 3.

### 1.4 Мёртвый код
Селектор мёртв, только если класс не найден **нигде**:
```bash
grep -rn "имя-класса" index.html offer.html privacy.html script.js
```
Обязательно проверь динамические имена в JS:
- шаблонные строки: `` `q-${level}` ``, `` `${block}__item` ``, `'is-' + state`;
- `classList.add/toggle/remove`, `className =`, `setAttribute('class'`;
- классы, которые создаёт SplitText (`.line`, `.word`, `.char` и маски), и классы клонов (`.glitch-layer`, клоны marquee);
- классы, которые будет генерировать MODX (`TODO(MODX)` в коде или `design-system.md`, раздел 15).

Если есть сомнение, правка уходит в CHECK. `_process-variants.html` и `my-version/` - черновики, на «живость» класса они не влияют.

Неиспользуемые `@keyframes`, неиспользуемые локальные `--переменные` (проверь grep и в CSS, и в JS, включая `setProperty('--...')`).

### 1.5 Хардкод → токен
Заменяем, только если значение **точно равно** токену в `design-tokens.css`: `16px` → `var(--space-4)`, если `--space-4: 16px`. «Почти равно» (`15px` → `--space-4`) - это VISUAL. Нужного токена нет: по `design-system.md` сначала добавляется токен, но это изменение общего файла, то есть SHARED, только с согласия пользователя.

### 1.6 Пустое и избыточное
- Пустые правила `{}`.
- Объявления, которые повторяют **уже вычисленное** значение из того же каскада: например, `display: block` у `div`, если его не перебивает ни одно правило выше по специфичности/порядку. Перед удалением проверь, что объявление не перебивает reset, утилиту или более раннее правило того же блока. Если сомневаешься, переводи в CHECK и проверяй снимком.
- `0px` → `0`, `0.5` вместо `.5` - **не трогать** без нужды: правка шумит в diff, а выигрыша нет.

### 1.7 Устаревшие префиксы
Удалять можно `-moz-`, `-ms-`, `-o-` и `-webkit-` у `transform`, `transition`, `animation`, `flex*`, `box-shadow`, `border-radius`, `box-sizing`.
**Оставлять:** `-webkit-backdrop-filter`, `-webkit-mask-*`, `-webkit-background-clip: text`, `-webkit-text-fill-color`, `-webkit-text-stroke`, `::-webkit-details-marker`, `::-webkit-scrollbar*`, `-webkit-tap-highlight-color`, `-webkit-font-smoothing`, `-webkit-line-clamp` и `-webkit-box` при нём, `-webkit-overflow-scrolling`. Это живые свойства Safari и Chrome.

## 2. CHECK: по одной правке, после каждой снимок

### 2.1 Перенос и объединение медиазапросов
Переносить мобильные правки блока в его основной кусок удобно, но это **меняет порядок в файле**. Безопасно, только если между старым и новым местом нет правил, которые с той же или большей специфичностью задевают **те же элементы и те же свойства**. Проверяй grep-ом селекторов элементов блока на диапазоне между двумя местами.

Объединение двух `@media (min-width: 768px)` блока в один - те же условия.

### 2.2 Группировка селекторов
`.a, .b { общее }` из двух одинаковых правил: специфичность не меняется, но меняется **позиция** одного из правил. Проверка как в 2.1.

`:is(.a, .b)` берёт специфичность **самого сильного** аргумента. `:is(.faq__q, #faq h3)` поднимет `.faq__q` до уровня id. Используй, только если все аргументы одинаковой специфичности.

`:where()` **обнуляет** специфичность, это всегда VISUAL-риск. Не использовать.

### 2.3 Локальные переменные блока
Значение повторяется 3 раза и больше внутри блока: можно вынести в `--<блок>-<что>` на корне блока. Риски:
- переменная наследуется вниз, во вложенные компоненты. Имя должно быть уникальным, с префиксом блока;
- `@property` с `inherits: false` ведёт себя иначе, не путать с обычными переменными;
- в `calc()` внутри медиа-условий переменные не работают (`@media (min-width: var(--x))` невалидно).

### 2.4 Упрощение селекторов
`.faq .faq__item .faq__question` → `.faq__question`: специфичность падает с 0-3-0 до 0-1-0. Правило может начать проигрывать другим правилам (`.faq__item[open] .faq__question`, утилиты, `.q-low ...`). Только с проверкой снимком **во всех состояниях**.

## 3. Опасные шорткаты: сбрасывают больше, чем видно

| Шорткат | Что молча сбрасывает |
|---|---|
| `background` | `background-image`, `-size`, `-position`, `-repeat`, `-clip`, `-origin`, `-attachment`. Убьёт `background-clip: text` у `.text-gradient` и градиенты из токенов |
| `font` | `line-height`, `font-variant-*`, `font-stretch`, `font-kerning`, `font-optical-sizing`, `font-size-adjust` |
| `transition` / `animation` | все неуказанные подсвойства, включая `transition-behavior`, `animation-composition`, `-timeline` |
| `border` | `border-image` |
| `mask` | все `mask-*`, включая `mask-composite`, и не сбрасывает `-webkit-mask-*` |
| `inset` с одним `auto` | вместо четырёх разных значений |
| `flex: 1` | это `1 1 0%`, а не `1 1 auto`: другой расчёт ширины |
| `grid-area`, `grid` | неявные `auto` и сброс `grid-auto-*` |
| `list-style`, `outline`, `text-decoration` | подсвойства, включая `text-decoration-thickness` |

`background-color: X` → `background: X` **нельзя**, если хоть одно правило блока ставит `background-image` или градиент.

## 4. Свойства с побочными эффектами: не удалять «как лишние»

Эти свойства меняют не только свою визуальную часть, но и **контекст** для потомков. Их удаление или добавление ломает слои, `position: fixed` внутри, `backdrop-filter`, sticky и маски:

- создают **stacking context**: `transform` (даже `translateZ(0)`), `opacity < 1`, `filter`, `backdrop-filter`, `mix-blend-mode`, `isolation: isolate`, `will-change` (с любым из перечисленных), `z-index` при `position` ≠ static, `contain: paint/layout`, `mask`, `clip-path`;
- создают **containing block для `position: fixed`**: `transform`, `filter`, `perspective`, `will-change: transform`, `contain: paint/layout`, `backdrop-filter`;
- ломают **`position: sticky`** у потомков: `overflow` ≠ visible у любого предка (в проекте hero/showreel на телефоне держатся на sticky, см. `pinSettings`);
- меняют **`min-width` у flex/grid-детей**: `overflow: hidden` или `min-width: 0` (хак против распирания длинным текстом).

`will-change`, `transform: translateZ(0)`, `isolation`, `contain`, `backface-visibility: hidden` в этом проекте почти всегда стоят намеренно (GPU-слой под GSAP или стекло). Без комментария рядом их не трогай, оставь в отчёте вопросом.

## 5. VISUAL: только в отчёт

- `clamp()` вместо ступенчатых медиазапросов: на промежуточных ширинах значения меняются.
- Замена значений на «близкие» токены, округление.
- Любые изменения `--ease-*`, длительностей, задержек, `@keyframes`.
- `gap` вместо `margin` у детей: другое поведение при переносе строк и у скрытых элементов.
- Смена `display` (flex ↔ grid), даже если «выглядит так же».
- Вынос в `.glass` / утилиты: меняет порядок применения.
- CSS-nesting: в проекте не используется, и поддержка браузерами ограничена (Safari до 16.5 и старые Android WebView).
- `aspect-ratio` вместо padding-хака, `dvh` вместо `vh` и подобные модернизации.

## 6. Чек-лист прохода по CSS блока

1. Собрать все правила блока со всех мест файла (карта из шага 1).
2. Дубли селекторов в одном контексте → 1.1.
3. Повторы свойств внутри правила → 1.2.
4. Длинные формы → шорткаты из 1.3; сверить с таблицей 3.
5. Хардкод, точно равный токену → 1.5.
6. Мёртвые селекторы, keyframes, переменные (grep по всем файлам) → 1.4.
7. Устаревшие префиксы → 1.7.
8. Разбросанные медиазапросы блока → 2.1 (CHECK).
9. Повторы значений 3+ раза → 2.3 (CHECK).
10. Всё, что меняет картинку, → раздел 5, в отчёт.
