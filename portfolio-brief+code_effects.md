## 1. Глобальные правила дизайна

- Тёмная палитра, секции с лёгким градиентом в холодных синих тонах; каждый градиент секции — свой оттенок/направление, чтобы секции визуально отличались, но оставались в одной системе.
- Стиль — премиальный glass morphism.
- Ощущение: качество уровня Awwwards, кинематографичный сторителлинг через скролл, крупная и кинетическая типографика, очень плавный скролл, премиальные интерактивные элементы, кинематографичные переходы, лёгкий film grain, полная адаптивность.
- SVG-иконки — спрайтом в index.html; на первой версии — сгенерированные иконки хорошего качества (заменяются позже).
- Изображения — из фотобанков/интернета как временные (заменяются позже).
- Шрифт — подходящий тематике, с поддержкой кириллицы, локально в проекте (woff2), без CDN-зависимостей.
- Hero и промежуточная секция — scroll video (скраббинг видео/последовательности кадров по скроллу), видео предоставляются отдельно:
  - Hero-секция — `Laptop_animation.mp4`.
  - Промежуточная секция (человек с макбуком) — `Character_animation.mp4`.
- В хедере/навбаре — элемент статуса доступности автора ("доступен" / аналог "занят" на будущее), с рядом расположенной ненавязчивой информационной анимацией (например, плавно пульсирующая точка-индикатор, без резких/ярких эффектов — статус должен читаться, но не отвлекать от навигации).
- Библиотеки — gsap.min.js, ScrollTrigger.min.js, ScrollSmoother.min.js, скачаны и подключены локально (без CDN).
  - **Важно (актуально с 2025 г.):** GSAP полностью бесплатен, включая все бывшие Club-плагины (SplitText, ScrollSmoother, MorphSVG, DrawSVG и т.д.) — лицензионных ограничений нет.
  - Для кинетической типографики использовать `SplitText` вместо самописного разбиения текста.
  - Плавный скролл — **ScrollSmoother** (Lenis не используем): теснее интегрирован с ScrollTrigger, удобнее для pin-сценариев с видео-скраббингом.
- Прелоадер — с прогресс-баром и логотипом, премиальная анимация.
- Индикатор прокрутки: десктоп — вертикальная полоса состояния, красиво оформленная; мобайл — горизонтальная полоса вверху navbar.
- HTML — методология BEM.
- Полная SEO-оптимизация, прохождение проверок Google PageSpeed.
- SEO-тексты — под сегмент разработки сайтов в РУ, с ключевыми фразами, но читаемые, без "воды".
- В текстовом контенте использовать короткое тире (-), длинное тире (—) не использовать.
- Cookie-уведомление с политикой конфиденциальности, кнопка "наверх", кнопка мессенджера (открывает popup) — всё в стиле дизайн-системы.
- Максимальная оптимизация производительности.

**Стек:** HTML/CSS/JS (vanilla), GSAP + ScrollTrigger + ScrollSmoother + SplitText, **MODX** (целевая CMS для последующей интеграции).

**Структура файлов (текущий этап — статический прототип):**

### Про MODX — важные ограничения на статическом этапе

Сайт в дальнейшем переносится на MODX. На этапе статической вёрстки это значит:

- **`sitemap.xml` и `robots.txt` не создаём** — будут генерироваться средствами MODX (штатно или через сниппеты/аддоны типа `Sitemap`, `Robots`). На статическом этапе достаточно оставить в `progress.md` пометку "перенести на MODX".
- Meta-теги, Open Graph, canonical, schema.org — верстать как статические `<meta>`/`<script type="application/ld+json">` в `<head>`, но именовать/структурировать так, чтобы при переносе в MODX было легко превратить в чанки/плейсхолдеры (`[[*pagetitle]]`, `[[*description]]` и т.п.) — то есть не хардкодить контент глубоко в разметку без возможности выделить в отдельные блоки.
- Все текстовые блоки (заголовки, описания секций, кейсы) стоит оформлять как чётко выделяемые HTML-блоки — это упростит будущую нарезку на MODX-чанки и TV-параметры.
- Форма обратной связи — верстать с расчётом на то, что backend-обработку (отправку, антиспам, письмо) позже возьмёт на себя MODX (например, FormIt) — на статическом этапе делать только фронтенд + базовую JS-валидацию, без реальной отправки на сервер.
- Изображения/иконки-спрайт держать в `/assets` с предсказуемой структурой — при переносе на MODX эта папка обычно мигрирует почти как есть в `assets`/`uploads`.

## 3. Технические требования (дополнение)

**Производительность:**
- WebP/AVIF с fallback, `loading="lazy"` + IntersectionObserver для медиа вне первого экрана.
- Preload только критичных ресурсов (hero-видео/шрифт).
- `font-display: swap`, субсеттинг шрифта (кириллица + латиница + цифры).
- Критический CSS инлайном для первого экрана.
- Скрипты — `defer`/`type="module"`.
- Fallback для видео-скраббинга на мобильных/медленном интернете (`prefers-reduced-data`, `saveData`) — статичный постер/последовательность изображений вместо видео.
- `prefers-reduced-motion` — упрощённая/отключённая версия тяжёлых анимаций.

**SEO (в рамках статического этапа, без sitemap/robots — см. раздел про MODX):**
- Title/description по секциям (под якоря), Open Graph + Twitter Card с картинкой.
- Canonical.
- Структурированные данные schema.org (`Person` или `ProfessionalService`).
- Favicon-сет (svg, ico, apple-touch-icon) + `manifest.json`.

**Доступность (a11y):**
- Проверка контраста текста поверх стеклянных панелей (WCAG AA).
- Видимые кастомные focus-состояния для клавиатурной навигации.
- Alt-тексты для изображений/иконок, aria-label для кастомных интерактивных элементов.

**UX-детали премиального уровня:**
- Кастомный курсор / magnetic-эффект на кнопках.
- Hover-раскрытие карточек портфолио (детали, лёгкий tilt/parallax).
- Скелетоны/плейсхолдеры изображений при загрузке (борьба с CLS).
- Форма: состояния loading/success/error, honeypot-поле против спама (реальная отправка — уже на MODX).
- **Spotlight-эффект по коду за курсором** (референс: https://stackbyte.dev/ — блок с примером кода в hero). На блоке с кодовым сниппетом (например, карточка кода в hero-секции) при движении мыши за курсором двигается свечение/подсветка, которая "проявляет" текст кода ярче под собой, а остальной код остаётся приглушённым/затемнённым.
  - Реализация: обёртка блока кода слушает `mousemove`, пересчитывает координаты курсора относительно контейнера и пишет их в CSS-переменные (`--x`, `--y`).
  - Поверх кода — слой с `radial-gradient(circle at var(--x) var(--y), rgba(255,255,255,.15), transparent 40%)`, который двигается вместе с курсором и подсвечивает текст под собой (через `mix-blend-mode` или как отдельный маскирующий слой поверх приглушённого базового цвета текста).
  - При уходе курсора с блока — свечение плавно гаснет (transition на opacity).
  - На мобильных (нет курсора) — эффект не нужен, либо заменяется на статичную лёгкую подсветку.

**Аналитика и согласие:**
- Место под Яндекс.Метрику/GA4 + управление через cookie-баннер (реальный consent, не декоративный).
- Ссылки в футере/cookie-баннере на политику конфиденциальности и оферту (страницы — заглушки на этом этапе).

## 3.1. Креативные принципы / уровень исполнения

Эти пункты — не отдельные фичи, а требования к тому, *как* реализуются уже перечисленные блоки, чтобы результат тянул на award-уровень, а не на "хороший темплейт с glass morphism".

1. **Signature interaction** — заложить один уникальный интерактивный элемент, придуманный под смысл бренда (а не скопированный с референсов), а не только стандартные паттерны индустрии. Решается как творческая задача на сессии 1, а не "как получится" по ходу.
2. **Словарь моушена** — единые именованные токены для кривых/длительностей анимаций (`--ease-premium`, `--duration-reveal` и т.п.), разные для entrance/hover/exit-состояний — чтобы вся хореография сайта ощущалась одной системой, а не разрозненными анимациями по секциям.
3. **Многослойный фон** — помимо базового градиента: тонкие анимированные mesh-градиенты/blob-формы, медленно дрейфующие и едва заметно реагирующие на скролл/курсор; film grain не статичный, а слегка "дышащий".
4. **Контекстный курсор** — курсор меняет форму/поведение в зависимости от того, что под ним (ссылка / кнопка / карточка портфолио / кодовый блок), а не просто magnetic-эффект на кнопках.
5. **"Живая" типографика** — fluid-типографика через `clamp()` вместо фиксированных breakpoint-размеров; text-reveal через маску/wipe/clip-path вместо простого fade; градиент в тексте заголовков в акцентных местах.
6. **Переходы как часть сторителлинга** — сквозной визуальный элемент (линия/частица/прогресс-индикатор), физически "путешествующий" между секциями, связывающий их в единый нарратив, а не просто независимый scroll-reveal на каждой секции.
7. **Прелоадер как мини-история** — не просто % загрузки, а короткая анимационная "завязка" истории сайта, задающая тон перед hero.
8. **Adaptive quality / graceful degradation** — деградация тяжёлых эффектов (blur/частицы) на слабых устройствах по факту производительности (простая FPS-проверка или `navigator.deviceMemory`/`connection.effectiveType`), в дополнение к `prefers-reduced-motion`.
9. **Микро-детали обратной связи** — кастомные (не браузерные) состояния валидации формы, hover/press-состояния кнопок с лёгким "физическим" откликом (scale/spring), а не просто сменой цвета.
10. **Самопроверка перед сдачей** — на сессии 12 прогнать готовый сайт по официальным критериям оценки Awwwards (Design / Usability / Creativity / Content) как финальный чек-лист самоконтроля.

**Инструмент-страховка от "нейрослопа" — Impeccable.**
Скилл для Claude Code (открытый исходный код, автор Paul Bakaus): слой явных анти-паттернов поверх генерации (переиспользованные градиенты, glassmorphism без причины, слабая иерархия, decorative-элементы без функции), плюс проверка spacing-сетки, типографической иерархии и контраста.

- В начале любой сессии, где идёт генерация/правка вёрстки (в первую очередь сессии 3, 4, 5, 7, 8, где выше риск "усреднения" без явного напоминания о токенах) — Claude должен сам проверить, установлен ли скилл, и если нет — установить:
  ```
  git clone https://github.com/pbakaus/impeccable.git
  cd impeccable
  claude skill add ./impeccable
  ```
- После установки — использовать его автоматически при генерации/ревью фронтенд-кода на этих сессиях, без дополнительного запроса от пользователя каждый раз.
- Это дополнение к дизайн-токенам (раздел 4.2) и креативным принципам (пункты 1-9 выше), а не замена — токены задают "что делать", Impeccable дополнительно проверяет "что не делать".

## 4.2. Дизайн-система — обязательный deliverable сессии 1

Создаётся на первом этапе (Discovery & архитектура), фиксируется в отдельных файлах `design-tokens.css` + `design-system.md` (см. структуру файлов) и прикладывается вместе с брифом во все последующие сессии — чтобы разные сессии/модели не "изобретали" стили заново и секции не расходились визуально.

Минимально достаточный набор токенов:

1. **Цвета** — базовая тёмная палитра + отдельный градиент под каждую секцию (конкретные HEX/HSL, направление), акцентный цвет, цвета текста (primary/secondary/muted) с проверкой контраста поверх glass-фона (WCAG AA).
2. **Типографика** — шкала размеров (h1…h6, body, caption), line-height, letter-spacing для крупных заголовков, распределение шрифтов (заголовки/текст).
3. **Spacing/grid** — единая шкала отступов (например, 4/8px-based), контейнер max-width, брейкпоинты.
4. **Glass-параметры** — переиспользуемый набор для стеклянных панелей: blur, background-opacity, border, тень (как CSS-переменные/класс, не "на глаз" в каждой секции).
5. **Radius/тени/переходы** — border-radius, стандартные easing/duration для transition — одна система для всех анимаций сайта.
6. **Именование** — BEM + CSS custom properties (`--color-bg-hero`, `--glass-blur` и т.п.), чтобы сессии 2-12 просто подключали токены.
